# 调试记录：为什么第一版策略的成功率只有 4%

这份记录保留完整的排查过程。结论本身（换动作表示）不难，难的是从"loss 很低但机器人不动"
定位到根因，而这个过程恰恰是项目里最有价值的部分。

## 症状

第一次完整训练（FM，PickCube，20000 步，45 分钟）：

- 训练 loss 从 2.06 收敛到 **0.067**，曲线漂亮
- 成功率 **4.0%**，平均步长 294/300（几乎全部超时）
- **五次评测（4k/8k/12k/16k/20k 步）的成功率精确相等，都是 4.0%**

最后这一条是最重要的线索：如果策略输出真的在影响结果，成功率不可能完全不随训练变化。

## 排查过程

### 1. 环境配置：找到一个真 bug，但不是主因

演示数据的 `control_mode` 是 `pd_joint_pos`（绝对关节角），而 `gym.make` 的默认是
`pd_joint_delta_pos`（增量）。策略输出的绝对角度被当成增量、还被裁剪到 [-1,1]。

修复后成功率 2%（在噪声范围内），**没有解决问题**。教训：找到一个 bug 不等于找到了那个 bug。

现在 `make_env` 会显式指定控制模式并 assert 校验。

### 2. 分离"环境问题"与"策略问题"

把演示动作原样回放进评测环境：**10/10 成功**。环境是对的，问题在策略。

### 3. 观测分布是否一致

| | 均值 | 标准差 |
|---|---|---|
| 训练数据图像 | 123.0 | 48.1 |
| 评测环境图像 | 123.4 | 48.0 |

一致，排除渲染/预处理不匹配。

### 4. 视觉特征的空间精度（线性探针）

用冻结 DINOv2 的 patch token 线性回归方块位置：

| 输入分辨率 | patch 数 | x 误差 | y 误差 | R² |
|---|---|---|---|---|
| 98 | 49 | 10.1 mm | 13.3 mm | 0.94 / 0.89 |
| 126 | 81 | 8.8 mm | 9.6 mm | 0.96 / 0.94 |
| 182 | 169 | 7.6 mm | 7.8 mm | 0.96 / 0.96 |
| 224 | 256 | 6.8 mm | 6.7 mm | 0.97 / 0.97 |

方块边长 20mm。分辨率有帮助但收益递减 —— 原图本来就只有 128 像素，放大不增加信息。
这说明视觉特征**不是**主要瓶颈（位置信息在里面，精度也够粗定位）。

### 5. 看机器人实际在做什么

录制 rollout 并对比演示：

| | 演示 | 策略 |
|---|---|---|
| TCP 到方块距离 | 0.163 → **0.003** m | 0.163 → **0.22** m（越走越远） |
| 夹爪 | 接近时张开，到位才闭合 | **第 4 步就闭合**并保持 |

策略一上来就闭合夹爪并远离方块，随即进入演示中从未出现的状态（夹爪闭合 + 远离目标），
彻底脱离训练分布。

### 6. 根因：动作表示的信噪比

对每种控制模式，用**当前关节角**线性回归动作，看能解释多少动作方差：

| 动作表示 | 可由"手臂当前在哪"解释的方差 | 真正的任务信号 |
|---|---|---|
| `pd_joint_pos`（原始演示） | **98.4%** | **1.6%** |
| `pd_ee_delta_pose` | 36.1% | 63.9% |
| `pd_joint_delta_pos` | 34.0% | 66.0% |

**这就是根因。** 绝对关节角表示下，动作的 98.4% 只是在复述"手臂当前的构型"，
真正决定任务成败的信号只占 1.6%；而模型在动作块第 0 步的残差误差是 17%。
**噪声比信号大一个数量级**，再怎么调参也学不出可用策略。

这同时解释了为什么 loss 那么低还是不工作：模型确实把 93% 的动作方差拟合掉了，
但那 93% 里绝大部分是"手臂在哪"这种无用信息。**低 loss 完全可以来自拟合无关信号。**

## 修复

把演示重放转换到 `pd_ee_delta_pose`（末端位姿增量），这也是 ManiSkill3 官方图像
baseline 采用的模式。对视觉驱动的策略，末端空间还有额外好处：视觉特征直接给出
"方块在哪"，末端增量就是"朝那个方向移动多少"，不需要模型隐式地解逆运动学。

## 可复用的教训

1. **成功率完全不随训练步数变化 = 策略输出没被有效使用**，先查这条链路而不是调超参
2. **先把"环境对不对"和"策略对不对"分开**：把专家动作原样回放，一步定位
3. **生成模型的 loss 绝对值不能作为验收标准**，尤其当目标里混着大量易预测的无关成分
4. **动作表示的信噪比是模仿学习的一等公民**，应该在训练前就用线性探针量一下

# 第二轮：抓取率 95%，成功率 6%

换成 `pd_ee_delta_pose` 之后策略确实学会了任务的主体动作。20000 步的 FM，
在线权重，20 个 episode：

| 指标 | 数值 |
|---|---|
| 起始 TCP→方块距离 | 0.165 m |
| 最近 TCP→方块距离 | **0.016 m**（20 局里最差的一局也只有 0.052 m） |
| 抓到过方块 | **95%** |
| 成功率 | **6%**（100 episode 评测） |

也就是说：**看得见方块、够得着、抓得稳，然后放不对地方。**

## 不是训练不够

先排除最容易想到的解释。连续指标在 12000 / 16000 / 20000 步上是
dmin 0.025 → 0.022 → 0.016 m、抓取率 80% → 90% → 95%，确实还在改善，
所以"再多训一些"看起来合理。但抓取率已经接近天花板，而成功率几乎不动。

采样步数消融更直接：1 步 9%、2 步 3%、5 步 5%、10 步 6%。**采样质量根本
不影响结果** —— 如果瓶颈在"生成的动作不够精确"，加采样步数应当有效。

## 根因：目标位置不在观测里

用第 4 节同一套线性探针（冻结 DINOv2 patch token + 岭回归，n=300），
分别回归方块位置和目标位置：

| 回归目标 | x / y / z 误差 | R² | 该量本身的标准差 |
|---|---|---|---|
| 方块位置 | 9.4 / 16.2 mm | **0.96 / 0.88** | 59 / 59 mm |
| 目标位置 | 55.6 / 48.9 / 80.6 mm | **−0.14 / −0.23 / −0.12** | 59 / 58 / 87 mm |

方块那一行与第 4 节的结果吻合，说明探针本身有效。目标那一行的 R² **三个轴全是
负的**，误差与目标值自身的标准差几乎相等 —— 探针的预测还不如直接输出平均值。

**目标位置在 `base_camera` 的图像里不存在。** PickCube 每局随机目标（z 方向
跨度 0.024–0.311 m），而策略的输入只有 RGB 和 9 维关节角，`goal_pos` 从来
没有被接进去。策略一直被要求预测一个依赖于它无法观测的信息的动作。

## 这同时解释了基线的数字

目标不可观测时，给定观测的动作分布在目标位置上是**真正多模态**的 —— 演示里
同一幅图像对应着通往各个不同目标的轨迹。于是：

- **FM 采样其中一个模态**，在目标恰好接近该模态时成功 → 6%
- **BC 回归条件均值**，即"平均目标位置"，在目标接近工作空间中心时成功 → 4%

两个数字都不是偶然。这也是个反讽：README 用"BC 的 MSE 最优解是条件均值，
而均值往往是非法动作"来论证要用生成模型；这里 FM 确实正确地建模了多模态，
但当模态的成因是**信息缺失**而非任务本身的多解性时，正确采样一个模态并不能
提高成功率。生成模型解决不了观测里没有的东西。

## 修复

`obs/extra/goal_pos` 在环境和演示数据里都有，只是 dataset 只读了 `agent/qpos`。
`use_goal=true` 把它接进 proprio（9 → 12 维）：

```bash
python -m src.train ++use_goal=true
```

StackCube 和 PegInsertionSide 的 obs 里没有 `goal_pos` —— 它们的目标是场景里的
实物（另一个方块、插孔），原则上可见。这两个任务的困难另有来源：演示里带
`hand_camera`，而为了让多任务的观测空间统一，我们只用了 `base_camera`。

## 追加的教训

5. **训练前该检查的不只是动作表示，还有观测充分性**：任务的目标量能不能从观测
   里线性恢复？用同一套探针，几分钟就能答，比训练一轮便宜几个数量级。
6. **"高抓取率 + 低成功率"是观测缺失的典型指纹**：动作链条的前半段依赖可见信息
   （物体在哪）所以学得好，后半段依赖不可见信息（目标在哪）所以退化成猜测。
7. **消融的解释力受限于它依附的指标**：成功率在个位数时，采样步数消融画出来的
   是一条噪声曲线，看不出任何结论——不是消融设计错了，是先得把成功率拉起来。
